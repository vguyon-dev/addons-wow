# Addons WoW

Addons World of Warcraft maison, pour Retail (Midnight, Interface 120105) et Forever (Interface 16001).
Les deux versions partagent la même API : un seul addon sert aux deux. Exception : LivresBiblio ne sert
qu'à Forever (ses livres n'existent pas sur Retail), son `.toc` ne déclare que 16001.

En combat, rien n'est appelé sur une fenêtre protégée : c'est noté et fait à la fin du combat. ## Arborescence

Un seul dépôt pour tous les addons, un dossier par addon à la racine :

```
addons-wow/
├── README.md            ce fichier : liste des addons et méthode
├── .gitignore
├── tests/               simulations hors jeu (jamais copiées dans AddOns)
├── .github/workflows/   publier.yml : tests puis version publiée à chaque push sur main
├── outils/              publier.py (paquets pour WowUp), paquet.ps1 (zip à la main), LISEZMOI.txt
├── CarnetDeSession/     un addon = un dossier, au même nom que son .toc
│   ├── CarnetDeSession.toc
│   ├── Reglages.lua     copie du module commun (réglages, icône commune)
│   └── CarnetDeSession.lua
└── <ProchainAddon>/
    ├── <ProchainAddon>.toc
    └── <ProchainAddon>.lua
```

Chaque dossier d'addon se copie tel quel dans `Interface\AddOns\`. Tous les addons partagent **une seule fenêtre de réglages**, « Mes addons », ouverte par l'icône commune (un engrenage) autour de la minimap ou par la commande de chaque addon : à gauche la liste des addons (point vert ou rouge ; clic droit = activer ou couper, Maj+clic = son panneau), à droite la page de l'addon (interrupteur général, un onglet par section, interrupteurs et curseurs, boutons d'action en bas), en haut une recherche qui trouve un réglage dans tous les addons. Tout en haut de la liste, la page « Quoi de neuf » (pas un addon : ni point ni interrupteur) montre les nouveautés, les plus récentes d'abord (`ns.NOUVEAUTES` dans `Reglages.lua` : pour annoncer du neuf, ajouter une entrée en tête avec la date du jour) ; chaque addon retient dans sa sauvegarde la date de la dernière nouveauté vue (`nouveautesVues`), et quand il y en a une plus récente, un seul message au chat à la connexion (même avec 23 addons, drapeau dans `_G.MesAddons`) et une pastille dorée sur l'entrée, jusqu'à l'ouverture de la page. Sous elle, « Partager mes réglages » donne un texte à copier (`VA1;Addon:cle=valeur,…`, les clés déclarées dans les options, interrupteurs et nombres seulement, jamais les listes) et un champ où coller celui d'un ami, avec « Appliquer » (les addons ou réglages inconnus sont ignorés, un texte abîmé est refusé avec un message clair). En haut de la page de chaque addon, l'interrupteur « Réglages propres à ce personnage » : la sauvegarde de l'addon garde `compte` (réglages communs) et `parPerso["Nom-Royaume"]` à côté de ses clés habituelles ; activé, le personnage a les siens (copiés depuis les réglages actuels), coupé, il retrouve ceux du compte. Les sauvegardes par personnage à part (`CarnetDeSessionPerso`, `ButinRapidePerso`, `GPSPerso`, `LivresBiblioPerso`) ne sont pas touchées. Le premier addon chargé crée la fenêtre (`_G.MesAddons`), les autres y ajoutent leur page par `ns.creerReglages` dans `Reglages.lua` ; chacun peut en plus réafficher son icône à part. Les autres fenêtres des addons (panneaux, alertes, bilan, liste de courses, barre du courrier) partagent le même visuel sombre et doré par `ns.habiller(cadre, { titre, fermer })`, aussi dans `Reglages.lua` ; seule la fenêtre du sac (`SacsRanges/Vue.lua`) garde son option « cadre du jeu ». Chaque `.toc` porte `## Category: Mes addons`. `Reglages.lua` est une copie identique dans chaque addon : le modifier dans l'un, puis le recopier dans les autres (les simulations vérifient qu'ils sont égaux). Un addon qui grossit peut
avoir plusieurs `.lua`, listés dans son `.toc`, et son propre `README.md`.

## Développer

Chaque dossier d'addon est relié aux dossiers AddOns du jeu par une **jonction** Windows :
une modification ici est vue par le jeu au prochain `/reload`, sans rien copier.

```powershell
$src = "D:\@DEV\Jeux\Modding\Wow\<Addon>"
foreach ($v in "_retail_", "_forever_") {
  New-Item -ItemType Junction -Target $src `
    -Path "D:\Program Files (x86)\Battle.net\World of Warcraft\$v\Interface\AddOns\<Addon>"
}
```

- Erreurs Lua : BugSack + BugGrabber (installés par CurseForge sur les deux versions).
  BugGrabber les écrit sur le disque à chaque `/reload` ou déconnexion, avec la pile d'appels,
  dans `<version>\WTF\Account\<compte>\SavedVariables\!BugGrabber.lua` : on peut les lire sans capture.
- Données d'un addon : `SavedVariables` (compte) dans `WTF\Account\<compte>\SavedVariables\`,
  `SavedVariablesPerCharacter` dans `WTF\Account\<compte>\<royaume>\<personnage>\SavedVariables\`.
- Vérifier la syntaxe avant de lancer le jeu : `wsl luac5.1 -p <fichier>.lua` (WoW utilise Lua 5.1).
- Simuler un addon hors du jeu, avec une fausse API WoW : `tests/` (exemple :
  `wsl lua5.1 tests/CarnetDeSession_simu.lua CarnetDeSession/CarnetDeSession.lua`, ou
  `wsl lua5.1 tests/QuetesAuto_simu.lua QuetesAuto/QuetesAuto.lua`,
  `wsl lua5.1 tests/MarchandAuto_simu.lua MarchandAuto/MarchandAuto.lua`,
  `wsl lua5.1 tests/MetiersAuto_simu.lua MetiersAuto/MetiersAuto.lua`,
  `wsl lua5.1 tests/ButinRapide_simu.lua ButinRapide/ButinRapide.lua`,
  `wsl lua5.1 tests/SacsRanges_simu.lua SacsRanges/SacsRanges.lua`, `tests/QuetesDuGroupe_simu.lua`, `tests/RapportErreurs_simu.lua`, `tests/AlerteRare_simu.lua`, `tests/LivresBiblio_simu.lua`, `tests/Conseiller_simu.lua`, `tests/SuiviQuetes_simu.lua`, `tests/Dialogues_simu.lua`, `tests/Tenues_simu.lua`, `tests/QuetesDispo_simu.lua`, `tests/Fenetres_simu.lua` ; contrôle des données : `node tests/donnees/quetes-dispo-controle.js`).
- Le nom du dossier doit être identique au nom du `.toc`.

## Partager

**Mises à jour automatiques avec WowUp (conseillé).** À chaque push sur `main` qui touche un addon,
l'action GitHub `.github/workflows/publier.yml` lance les tests hors jeu. S'ils passent, elle publie une version
(onglet *Releases*, numérotée `AAAA.MM.JJ.<n° du run>`) avec deux paquets fabriqués par
`outils/publier.py` : `addons-wow-<version>.zip` pour Retail et `addons-wow-<version>-forever.zip` pour
Forever (LivresBiblio n'est que dans celui-ci), plus `release.json`, la fiche au format du packager BigWigs
que WowUp lit pour choisir le bon paquet. Un test qui échoue bloque la publication.

Installation chez la personne, une seule fois :
1. Installer WowUp (https://wowup.io, gratuit) et le laisser trouver WoW ; choisir Forever ou Retail en haut.
2. *Get Addons* > *Install from URL*, coller `https://github.com/vguyon-dev/addons-wow`, puis *Install*.
3. Si elle avait copié les addons à la main avant, WowUp les remplace : les réglages sont gardés,
   ils vivent dans `WTF\`, pas dans les dossiers des addons.

Ensuite WowUp propose chaque nouvelle version (ou la pose seule si la mise à jour automatique est
cochée dans ses options) ; un `/reload` ou une relance du jeu la charge.

**À la main.** Le dépôt est public : la personne clique sur **Code > Download ZIP**, ouvre le dossier
`addons-wow-main` et copie seulement les dossiers d'addons (pas `tests`, `outils` ni `.github`), puis suit
`outils/LISEZMOI.txt`. `pwsh -File outils\paquet.ps1` fabrique aussi un zip avec tous les addons et la notice
dans `Téléchargements\@Claude\Telechargements\AddonsWow\`.
